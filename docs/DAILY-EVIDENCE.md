# Daily news: evidence, verification, then audio

**Scope:** the six-feed daily track, not the Memory ledger. Source data and providers are private. These are code paths, not findings about the historical short laptop recordings.

## From an eligible event to speech

1. Form groups from the seven-day window ending **at** the cutoff, then apply the editorial hold. Share that index between listeners. Screen topics before planning; no match does not purchase general news. Within a group, use bounded evidence depth, native language and date to choose a lead. Keep the ranked supported lead event, then prefer additional supported events with details; preserve rank order among the chosen events. Two or three stories at normal caps, one at very short caps.
2. For candidate reports, scan the **whole** `text` field in server memory. Use sentence and paragraph boundaries, retaining exact source offsets, including wrapped lines. Score subject/topic ties, developments, quantities/dates, statements, terms and concrete detail. Skip title echoes, common ads, notices, repeated or disconnected material. Fixed pools across five body regions keep the beginning from exhausting the candidates. Retain at most 10 distinct passages / 3,600 source characters per primary, not a raw prefix.
3. A passage has a focus: a complete sentence or, in an oversized sentence, a bounded standalone clause at a safe semicolon boundary. Do not silently truncate mid-claim. Omit oversized material when a safe split cannot retain its meaning/qualification. For an ambiguous subject/attribution or required following condition, select at most one directly adjacent sentence in the same paragraph, **800 characters total**, and retain both the focus and exact window. The neighbour isn't another fact to join to the focus. For secondary coverage require an eligible, different outlet, not a translation/copy, with a shared anchor and a concrete novel figure, condition, reporting dimension or attributed actor. Be conservative across languages. At most one secondary, 3 candidate passages / 1,400 characters; a second article isn't a success metric.
4. Build a per-event outline: development, distinct reported quantities/terms/statements when available, then other nonduplicate details. Only the offered facts (max 6 per event) and their metadata go to the writer. The server resolves its articleId + evidenceIndex, not a model-invented excerpt. Check source offsets, one sentence, non-echo/non-copy, language, timing, quantities and units, condition retention and duplicates. In a separate request a strict checker evaluates each remaining claim **only against its own actual window**. It may use other *claims* only to reject repetition. Require one complete, correctly keyed verdict/reason per claim, fail closed on an invalid batch. Automatic checking is not human approval.
5. Fit full, linked sentences in story prefixes under `floor(min(maxMinutes,3) * 128)` words including the opening; estimate speech at 140 wpm. At a three-minute cap require **140 verified factual words**; prefer 180–300 when supported, not filler. At smaller caps scale those targets by `maxMinutes / 3` (round down). Also require two verified events if at least two selected events have body evidence, and multiple sentences for up to two detail-bearing events when available. Freestanding punctuation is not a factual word. A short partial **never** passes just by covering enough event IDs. If useful evidence remains, allow at most one targeted addition (up to 6 foci across the edition), not a second full draft. At the three-minute planning budget a repair may use up to two distinct reserves beyond a story’s initial six; no automatic expansion of a script that already passed. Prefer untouched facts; send missing-fact references and error categories, never ask for a number-free rewrite. Recheck every addition. Do not overwrite successful sentences. No retry loop for an HTTP error, timeout or bad verification response.
6. An insufficient edition is **transcript only**: `audioStatus:not_requested`, null URL/duration, zero TTS characters. No ElevenLabs call **or cache lookup**, including after verification failure. The reason is in the script diagnostics. For a sufficient edition only, TTS receives the final ordered segments joined by two newlines; the audio key binds that text, voice, model and format.
7. Walk complete MPEG frames and compare the presentation clock to **both** duration bounds. Reject inconsistent declared Xing/Info counts. Decode fresh bytes to the end before atomic admission. Match the recording digest and transcript receipt and remeasure on cache hits; check the exact bytes again before range/whole-file delivery. At the three-minute daily planning budget (also used for larger caps), require **at least 60 seconds**; no floor for shorter custom editions or Memory. A Xing/Info header is not playable speech; recognized LAME/FFmpeg gapless delay and end padding do not count as presentation time. No timing decision uses rounded seconds. A short MP3 returns `below_minimum_duration`, no URL and null playback duration. A fresh rejected file is not published. Corrupt/short cache hits do not trigger a paid regeneration. There is no audio editing or automatic retry.

## Read a short-edition diagnostic

Use `response.diagnostics` or the same object in private `generated/usage.jsonl` (join on `id` / `briefingId`). No API keys, request/response payloads, transcript text or source excerpts in diagnostics. `generated/fact-audit.jsonl` stores ordered pointers and hashes, **not** quoted passages. Resolve those privately against the exact input export as described in [the contract](../shared/CONTRACT.md).

- `eligibleEvents`: date-eligible event count after editorial hold, before topic filtering. `selectedEvents`: primary event IDs with per-article body character counts, examined spans, qualifying spans (pre-dedup), bounded available evidence, discard categories and per-event initial outline size. These are not claims the verifier has approved.
- `attempts`: offered evidence count, draft sentences/words **before rejection**, submitted/approved sentences and approved words per batch, rejection histogram, and per-offered-fact IDs/states including not drafted and unverified batches. Top-level draft and rejection counts sum across attempts; final fitting can also report `time_budget`. Compare stages rather than treating combined draft words as delivered speech.
- `minVerifiedWords`, `preferredVerifiedWords`, `finalVerifiedSentences`, `finalVerifiedEvents`, `finalVerifiedWords`, `verifiedEstimatedSeconds`: only independently approved **delivered** summaries. `finalEventIds`, `headlineSegments`, `finalSpokenWords` and `estimatedDurationSeconds` describe the **whole** delivered transcript, including opening and titles. `actualMp3DurationSeconds` is measured from valid frames, otherwise null. For a timing refusal this is the unrounded presentation clock that failed, not the script estimate. A timeable file can still fail decoding or integrity.
- `generationMode`, `qualityStatus`, `gateFailure`, `repairAttempted`, `repairApplied`, `fallbackReason`, `fallbackKind`: distinguish insufficient material, empty/short drafts, rejected claims, partials, and emergency titles. `providerFailures` identifies writer / verifier / repair / repair_verifier / TTS, sanitized category and HTTP status when known. Malformed verdicts or timeouts do not become successful scripts. Known token usage before a failure is retained; do not interpret `usageComplete:false` as a complete bill.
